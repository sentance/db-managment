# ADR 0004: Шифрование секретов и мастер-ключ

**Статус:** принято, 2026-10-21

## Решение
- Все пароли и TOTP-секреты хранятся в таблице `secret` как AES-256-GCM (nonce 96 бит). Назначение секрета привязано как AAD, чтобы шифротекст нельзя было подставить в чужую запись.
- Мастер-ключ (32 байта) лежит в `deploy/secrets/master.key` и передаётся контейнеру как docker secret. **В metadata DB и её бэкапах ключа нет.**
- У каждого шифротекста хранится `key_id` (первые 4 байта SHA-256 ключа). Старые ключи можно подключить через `pgcp.crypto.previous-key-files` для расшифровки во время ротации.
- `install.sh` предупреждает, что ключ нужно сохранить офлайн. Порядок восстановления описан в `docs/runbooks/disaster-recovery.md`.

## Последствия
- Без мастер-ключа сохранённые пароли не восстановить. В этом случае роли получают новые пароли через Rotate: данные в PostgreSQL не страдают.
