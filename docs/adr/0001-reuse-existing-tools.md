# ADR 0001: Переиспользовать существующие инструменты

**Статус:** принято, 2026-10-21

## Контекст
ТЗ запрещает писать собственный storage engine и систему бэкапов, если нужное уже есть в open source. Кандидаты проверены на актуальность и лицензии.

## Решение
| Задача | Инструмент | Лицензия | Почему |
|---|---|---|---|
| Физические бэкапы, WAL, PITR | pgBackRest (2.60 вышел 2026-10-18; в PGDG trixie пока 2.59.3) | MIT | full/diff/incr, S3/R2, шифрование, `info --output=json`; уже работает в prod на tgok |
| Логические бэкапы, ветки | pg_dump / pg_restore | PostgreSQL | стандарт; pgcp только оркестрирует |
| Thin clones | DBLab Engine CE | Apache 2.0 | CoW на ZFS, REST API; опционально, Phase 4 |
| SQL-редактор | CloudBeaver (уже есть на tgok) или pgAdmin | Apache 2.0 / PostgreSQL | ТЗ допускает интеграцию; встраиваем ссылкой |

**Databasus** (Apache 2.0) не интегрируем: у него нет документированного API для встраивания, и он дублирует pgBackRest. Это самостоятельное приложение, а не библиотека.

## Последствия
- Код pgcp — оркестрация, метаданные, безопасность и UI.
- Версии внешних инструментов закреплены (pgBackRest в Dockerfile, образы по major) и обновляются осознанно.
